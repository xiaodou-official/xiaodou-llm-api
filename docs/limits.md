# 限额、并发与配额

> 适用版本：v1.0.0 ｜ 更新：2026-11-22 ｜ 返回 [README](../README.md)

## 1. 默认限额

| 项 | 默认值 | 说明 |
| --- | --- | --- |
| 请求频率 | **60 次/分钟 / 令牌** | 超过返回 `429 rate_limit_exceeded` |
| 单请求体 | 服务端与网关限制 | 超限返回 413；长文本请分段 |
| 上下文长度 | 由模型决定 | 超限通常 400 或上游错误 |
| 最大输出 | 由模型决定 | 触达上限时 `finish_reason=length` |
| 账号额度 | 由充值决定 | 额度耗尽返回 `402 insufficient_quota` |

需要更高并发或专属配额：在控制台提交申请，或邮件 <contact@yuzhideep.com> 说明 QPS、模型与预计月用量。

## 2. 并发怎么排

- **按模型分开限流**：不同模型在上游的配额不同，别用一个全局并发数套所有模型。
- **令牌分开**：生产、测试、批量任务各一枚令牌，出问题能单独禁用。
- **队列而非裸并发**：批量任务用队列 + 固定 worker 数，比一次性 `Promise.all` 稳。
- **失败降级**：主模型 5xx 连续 3 次，切备用模型跑完本轮，再异步重试主模型。

## 3. 额度与账单

- 充值兑换为平台配额，**不可提现、不可转让**。
- 已消耗配额不退款；因平台原因长时间不可用的，可按用户协议协商补偿。
- 每笔调用在控制台「日志」页可查：时间、模型、输入/输出 tokens、扣费、状态码。
- 需要月度对账：按「日志」导出，别用余额接口反推（余额是快照，不是流水）。

## 4. 数据留存

- 账号信息与调用记录按用户协议与隐私政策处理。
- prompt 与输出会经过平台转发到上游；**不要提交密码、证件号、银行卡号、客户名单**。
- 需要「零留存」类承诺的场景，请直连你已签署数据处理协议的官方端点。

## 5. 可用性

- 平台按「现状」提供服务，不承诺 100% 可用；上游中断、限流、内容审核拒绝属于上游行为。
- 上游切换、模型下架会尽量提前在控制台公告，并同步到 [CHANGELOG](./changelog.md)。
- 生产环境请自备降级路径：至少两个模型、至少一条直连官方通道。
